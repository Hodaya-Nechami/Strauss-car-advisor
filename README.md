# יועץ הרכב של שטראוס

בוט בעברית שעונה לעובד: "מה יקרה לנטו שלי אם אחליף רכב, אעבור לחשמלי או אוותר על הרכב?"
האקתון AI קוד פתוח 2026, אתגר בשיתוף שטראוס.

כל מספר שהעובד רואה מגיע ממנוע חישוב בקוד, לא ממודל השפה. כשחסר נתון שרק החברה יודעת, הבוט שואל נציג אנושי וממשיך מאותה נקודה כשהנציג עונה.

## הפעלה בפקודה אחת (Docker)

צריך Docker Desktop (או Docker Engine + Compose). לא צריך Node.js מותקן על המחשב.

1. יוצרים את `apps/web/.env` עם מפתח API אחד לפחות (ראו "מפתחות" למטה). אפשר להעתיק את `apps/web/.env.example`.
2. מרימים:
   ```
   docker compose up --build
   ```
   ופותחים `http://localhost:3000`. אם פורט 3000 תפוס: `WEB_PORT=3900 docker compose up --build`.

מאגר שווי השימוש מיובא אוטומטית מה-CSV בעליה הראשונה. הוא והיסטוריית השיחות נשמרים ב-SQLite בתוך volume בשם `strauss_data`,
ושורדים `docker compose down` ו-`docker compose up` מחדש. למחיקה מלאה: `docker compose down -v`.
לייבוא מחדש של המאגר ידנית: `docker compose run --rm data-import`.

## הפעלה לפיתוח (Node.js)

צריך Node.js 20 ומעלה.

```
npm install
npm run data:import   # מייבא את מאגר שווי השימוש ל-SQLite (פעם אחת)
npm run dev           # http://localhost:3000
```

בדיקות, בלי מפתח ובלי אינטרנט (179 בדיקות):
```
npm test
npm run typecheck
```

## מפתחות

הקובץ `apps/web/.env` (או `.env.local`) לא עולה לגיט. ב-`apps/web/.env.example` יש את כל האפשרויות עם הסבר.

**מודל שפה.** מספיק מפתח אחד. עם כמה מפתחות, הבוט עובר אוטומטית לספק הבא כשלספק נגמרת המכסה או שהוא לא זמין, אפילו באמצע חישוב, וחוזר אליו אחרי זמן המתנה.

| ספק | איפה מקבלים | עלות | נטפרי |
| --- | --- | --- | --- |
| Gemini | `aistudio.google.com`, Get API key | חינם, מכסה יומית | פתוח |
| Cohere | `dashboard.cohere.com`, API Keys | חינם, 1,000 קריאות בחודש | פתוח |
| Mistral | `console.mistral.ai`, API Keys | חינם, תוכנית חינמית | פתוח |
| OpenRouter | `openrouter.ai`, Keys | חינם, 50 בקשות ביום | פתוח |
| Groq | `console.groq.com`, API Keys | חינם, מכסה יומית | חסום |
| OpenAI | `platform.openai.com`, API keys | בתשלום | |
| Claude | `platform.claude.com` | בתשלום | |

הסדר הרגיל: Gemini, Cohere, Mistral, OpenRouter, Groq, ואחריהם הספקים בתשלום כגיבוי. כדי שהספקים בתשלום יהיו ראשונים: `LLM_PROVIDER=claude,openai`.
בגרסאות החינמיות, הספקים עשויים להשתמש בקלט לאימון. לכן עובדים רק עם נתוני הדוגמה, לא עם נתוני שכר אמיתיים.

**כניסה למערכת.** בלי הגדרה נוספת האתר פתוח, ומסך הנציג מוגן בסיסמה משותפת (`REP_PASSWORD`).
כשמגדירים `AUTH_SECRET`, `AUTH_GOOGLE_ID` ו-`AUTH_GOOGLE_SECRET`, כל המערכת דורשת כניסה עם Google:
- `REP_EMAILS`: המיילים של הנציגים. רק הם נכנסים ל-`/rep`.
- `ALLOWED_EMAILS`: אילו עובדים נכנסים לאתר, דומיין (`@strauss-group.com`) או כתובות מלאות. ריק: כל חשבון Google.

**שליחת מייל (לא חובה).** בלי הגדרה, כפתור "שלחו לי את כל האפשרויות" פותח לעובד מייל מוכן בתיבה שלו. עם `BREVO_API_KEY` ו-`MAIL_FROM` המערכת שולחת בעצמה מייל מעוצב, ורק לכתובת שאיתה העובד נכנס.

## פריסה ב-Render

הקובץ `render.yaml` הוא Blueprint שבונה את האתר מה-Dockerfile, מהענף `main`, בתוכנית החינמית.

1. ב-Render: New, Blueprint, ובוחרים את הריפו.
2. ממלאים ב-dashboard את המפתחות (הם מוגדרים `sync: false` ולא נשמרים בקובץ), וב-`AUTH_URL` את הכתובת הציבורית של השירות. `BREVO_API_KEY` ו-`MAIL_FROM` לא חובה.
3. עם כניסת Google: מוסיפים ב-Google Cloud Console את הכתובת `https://<השירות>.onrender.com/api/auth/callback/google`, ובמסך ה-OAuth consent לוחצים Publish app.

כל push ל-`main` מפעיל פריסה מחדש.

## איך זה עובד

1. העובד כותב בצ'אט. השרת שולח את השיחה למודל השפה עם ההנחיות (`packages/agent/src/prompt.ts`) ועם רשימת הכלים.
2. המודל לא מחשב בעצמו. הוא מפעיל כלים: שמירת נתוני שכר, קטלוג רכבים, חיפוש במאגר, בדיקת זכאות, השוואה, דירוג החלופות ושאלה לנציג.
3. הכלים קוראים למנוע החישוב. המנוע מחזיר מספרים מדויקים, והמסך מציג אותם בכרטיס השוואה.
4. כשחסר נתון שרק החברה יודעת, הבוט שולח שאלה לנציג ומציג בינתיים את מה שכבר חושב. הנציג רואה את השאלה ב-`/rep` ועונה, והמסך של העובד מתעדכן לבד. תשובת נציג נכנסת רק כהודעת מערכת, כך שעובד לא יכול להתחזות לנציג.
5. כל שיחה נשמרת ב-SQLite (`CHATS_DB_PATH`), כולל היסטוריית ההודעות לספק, יומן הכלים והשאלות לנציג. הכתיבה לשיחה עוברת דרך נעילה, כדי ששתי פעולות לא יכתבו באותו זמן.

## מה עובד

- **דיוק:** המנוע מוציא בדיוק את נטו הייחוס של המארגנים לכל 6 העובדים, כולל מס, ביטוח לאומי, גילום החזר החשמל וטקסט "למה". מקרי קצה בדוקים: ויתור בקבוצה ב', תפקיד שטח, בחירה מקבוצה גבוהה, מסלול משפחתי, פלאג-אין, השתתפות חסרה.
- **מצב הדגמה:** 6 העובדים לדוגמה בלחיצה, חישוב מיידי בלי מודל שפה, ובדיקה חיה מול נטו הייחוס.
- **כרטיס השוואה:** כל רכיבי החישוב, פירוט "איך חושב?", החלפת רכב וחישוב מחדש בלי הבוט, תרשים "לאן הלך כל שקל" (פירוק ההפרש לסיבות), ואיך ייראה התלוש של החודש הבא עם החלופה.
- **מה הכי משתלם לי?** דירוג כל החלופות לפי הנטו, בגרף עם קו "היום".
- **העלאת תלוש:** המודל קורא רק את מה שמודפס, הקוד מחשב, העובד מאשר. התלוש לא נשמר.
- **טופס "הנתונים שלי":** תיקון שכר, פנסיה ונקודות זיכוי, עם חישוב מיידי.
- **מסך נציג `/rep`:** שאלות פתוחות, טופס תשובה, היסטוריה. כניסה בסיסמה או עם Google.
- **שליחת כל האפשרויות למייל,** מהמשתלמת ביותר, עם ההשוואה האחרונה. המייל נבנה בשרת מהשיחה השמורה.
- **עיצוב:** הדמות "נטבוט", מכונית מצוירת ב-SVG שמגיבה לשיחה. תמונות רכבים מוויקישיתוף (Creative Commons, עם קרדיט), וציור לפי סוג המרכב כשאין תמונה.
- **CI:** כל PR ל-`main` מריץ `npm ci`, typecheck, בדיקות, `npm run build` ובניית תמונת Docker.

## פרטיות ואבטחה

- מספר של 8-9 ספרות (כמו תעודת זהות) מוסתר בטקסט החופשי לפני שהוא נשמר ונשלח למודל.
- הגבלת קצב על הצ'אט, קריאת התלוש, שליחת המייל ומסך הנציג. מאחורי פרוקסי אמין (כמו ב-Render) מגדירים `TRUST_PROXY=1`, כדי שההגבלה תהיה לפי כתובת IP.
- המפתחות רק במשתני סביבה. `.env` ומסדי הנתונים לא עולים לגיט.

## קבצי ההגדרות (`config`)

- `rules.json`: תקציבים, קבוצות, מסלול משפחתי, החזר חשמל, שיטת חישוב הנטו. נבדק עם zod בטעינה, ושגיאה בקובץ מוצגת בבירור.
- `catalog.json`: 20 הרכבים בקטלוג (מגיליון "קטלוג רכבים").
- `occupations.json`: 14 העיסוקים, ומי מהם יכול לוותר על רכב.
- `sample-employees.json`: 6 העובדים לדוגמה.
- `reference-results.json`: נטו הייחוס של המארגנים. הבדיקות משוות אליו.

אם האקסל מתעדכן: `npm run config:build`. אחרי שינוי בקבצי ההגדרות מפעילים את השרת מחדש.

## החלטות שקיבלנו

- **פלאג-אין לא מקבל החזר חשמל.** הכלל מדבר על "רכב חשמלי". אפשר לשנות ב-`rules.json` בשדה `electric.eligibleDrives`.
- **רכב נוכחי שלא בקטלוג:** הבוט מחפש אותו במאגר רשות המסים לפי תוצר, דגם ושנת רישום. אם יש יותר מהתאמה אחת, הוא שואל את העובד או את הנציג.
- **מפתח החיפוש במאגר** כולל תמיד את קוד סוג הרכב. בלי זה, ATTO 3 ו-TANG מקבלים אותו מפתח.
- **עמודת ההנעה ב-CSV:** הכותרת מטעה. הפירוש הנכון: 0 בנזין, 1 היברידי, 2 פלאג-אין, 3 חשמלי. נבדק מול כל 20 רכבי הקטלוג.
- **ההפרש שמוצג לעובד** הוא נטו מעוגל בחלופה פחות נטו מעוגל היום, כמו אצל המארגנים.
- **מודל השפה:** מפתחות חינמיים עם מעבר אוטומטי, לפי ההמלצה של ארגז הכלים של ההאקתון. מפתח אחד לכל ספק: לא עוקפים מכסה בעזרת כמה מפתחות. Gemini 3.8 Flash עם חשיבה נמוכה: קיצר תור מ-53 שניות ל-9, עם אותן תוצאות, כי החישוב נעשה בקוד.

## מגבלות ידועות

- **Render בתוכנית החינמית:** אין disk קבוע. מאגר שווי השימוש נבנה מחדש בכל עליה, אבל **היסטוריית השיחות נמחקת בכל restart או פריסה.** השירות גם נרדם אחרי זמן בלי שימוש, והבקשה הראשונה איטית. ב-Docker מקומי הנתונים נשמרים.
- **ספקים חינמיים:** מכסות קטנות, ולפעמים איטיות. Cohere ו-Mistral לא נבדקו עם מפתח אמיתי.
- **הגבלת הקצב** נשמרת בזיכרון של השרת. עם כמה שרתים היא לא משותפת ביניהם.
- **תמונת הקרניבל** חסרה (ממתינה לאישור נטפרי). מוצג ציור במקומה.
- **אין עדיין בדיקות קצה לקצה בדפדפן** (Playwright).

## מה נדרש לפיילוט אמיתי

- ספק מודל בתשלום עם הסכם שלא מאמן על הנתונים (Claude או OpenAI), כי נתוני שכר אמיתיים לא נשלחים לספק חינמי.
- מסד נתונים קבוע (disk קבוע או Postgres), כדי שהיסטוריית השיחות תשרוד פריסה.
- כניסה עם Google מוגבלת לדומיין החברה (`ALLOWED_EMAILS=@strauss-group.com`), ורשימת נציגים ב-`REP_EMAILS`.
- חיבור לנתוני השכר ולרשימת הרכבים של החברה במקום קבצי הדוגמה.
- בדיקות קצה לקצה לתסריטים המרכזיים.
