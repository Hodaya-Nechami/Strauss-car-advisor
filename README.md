# יועץ הרכב של שטראוס

בוט בעברית שעונה לעובד: "מה יקרה לנטו שלי אם אחליף רכב, אעבור לחשמלי או אוותר על הרכב?"
האקתון AI קוד פתוח 2026, אתגר בשיתוף שטראוס.

## הפעלה מהירה

צריך Node.js 20 ומעלה.

```
npm install
npm test
```

`npm test` מריץ את בדיקות מנוע החישוב. כולן חייבות לעבור לפני כל מיזוג.

## מבנה הפרויקט

| תיקייה | מה יש בה | אחראית |
| --- | --- | --- |
| `packages/engine` | מנוע החישוב: נטו, זכאות, השוואה. קוד טהור, בלי מודל שפה | שותפה 1 |
| `packages/agent` | כלי הבוט, ההנחיות שלו ולולאת השיחה (עוד לא נבנה) | שותפה 1 |
| `packages/data` | טעינת מאגר רשות המסים, טעינת כללים עם ולידציה (עוד לא נבנה) | נחמי |
| `apps/web` | האתר: מסך עובד, מסך נציג, API (עוד לא נבנה) | שתינו |
| `config` | קבצי ההגדרות. משנים כאן, לא בקוד | נחמי |
| `data/source` | קבצי האתגר המקוריים, כמו שהתקבלו | - |
| `scripts` | סקריפט שממיר את האקסל לקבצי ה-JSON שב-`config` | נחמי |

## קבצי ההגדרות (`config`)

- `rules.json`: תקציבים, קבוצות, מסלול משפחתי, החזר חשמל, שיטת חישוב הנטו.
- `catalog.json`: 20 הרכבים בקטלוג (מגיליון "קטלוג רכבים").
- `occupations.json`: 14 העיסוקים, ומי מהם יכול לוותר על רכב.
- `sample-employees.json`: 6 העובדים לדוגמה.
- `reference-results.json`: נטו הייחוס של המארגנים. הבדיקות משוות אליו.

אם האקסל מתעדכן: `python scripts/excel-to-json.py .`

## מצב נוכחי

- **מנוע החישוב מוכן ובדוק.** הוא מוציא בדיוק את נטו הייחוס של המארגנים לכל 6 העובדים: נטו, מס, ביטוח לאומי, גילום החזר החשמל וחלק העובד במסלול המשפחתי.
- **מקרי קצה בדוקים:** ויתור בקבוצה ב', תפקיד שטח שלא יכול לוותר, בחירה מקבוצה גבוהה, 3 ילדים במסלול המשפחתי, פלאג-אין, השתתפות חסרה, קבוצה שלא תואמת לעיסוק.

## החלטות שקיבלנו

- **פלאג-אין לא מקבל החזר חשמל.** הכלל מדבר על "רכב חשמלי". אפשר לשנות ב-`rules.json` בשדה `electric.eligibleDrives`.
- **רכב נוכחי שלא בקטלוג:** הבוט שואל תוצר, דגם ושנת רישום, ומחפש במאגר רשות המסים. אם יש יותר מהתאמה אחת, הוא שולח שאלה לנציג.
- **ההפרש שמוצג לעובד** הוא נטו מעוגל בחלופה פחות נטו מעוגל היום, כמו אצל המארגנים. כך המספרים על המסך מסתכמים.
- **המנוע אף פעם לא מנחש.** כשחסר מידע הוא מחזיר רשימת חוסרים, והבוט שואל את העובד או את הנציג.

## נחמי: מאיפה להתחיל

1. להעלות את המאגר ל-GitHub ולהגדיר הגנה על `main` (משימה N1).
2. להוסיף GitHub Actions שמריץ `npm ci`, `npm run typecheck` ו-`npm test` (משימה N2).
3. לבנות את `packages/data`: ייבוא `data/source/value-of-use-2026.csv` למסד SQLite (משימה N3). הקובץ בקידוד cp1255 (windows-1255), וצריך לנקות רווחים מכל השדות.
4. **חשוב:** מפתח החיפוש של שווי שימוש חייב לכלול גם את קוד סוג הרכב. בלי זה, ATTO 3 ו-TANG מקבלים אותו מפתח.
5. החוזה המשותף נמצא ב-`packages/engine/src/types.ts`. שינוי שם דורש תיאום בינינו.

תוכנית העבודה המלאה: `תוכנית-עבודה-וחלוקה.md`.
