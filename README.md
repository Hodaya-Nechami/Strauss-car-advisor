# יועץ הרכב של שטראוס

בוט בעברית שעונה לעובד: "מה יקרה לנטו שלי אם אחליף רכב, אעבור לחשמלי או אוותר על הרכב?"
האקתון AI קוד פתוח 2026, אתגר בשיתוף שטראוס.

## הפעלה

צריך Node.js 20 ומעלה ומפתח API של מודל שפה. אפשר בחינם לגמרי.

1. מתקינים את החבילות:
   ```
   npm install
   ```
2. מקבלים מפתחות חינמיים, בלי כרטיס אשראי. מספיק אחד, ועדיף כמה, מפתח אחד לכל ספק:

   | ספק | איפה מקבלים | מה חינמי | נטפרי |
   | --- | --- | --- | --- |
   | Gemini | `aistudio.google.com`, Get API key | מכסה יומית | פתוח |
   | Cohere | `dashboard.cohere.com`, API Keys | 1,000 קריאות בחודש | פתוח |
   | Mistral | `console.mistral.ai`, API Keys | תוכנית חינמית | פתוח |
   | OpenRouter | `openrouter.ai`, Keys | 50 בקשות ביום, מודלים חינמיים | פתוח |
   | Groq | `console.groq.com`, API Keys | מכסה יומית | חסום |

3. יוצרים את הקובץ `apps/web/.env` (או `.env.local`) עם המפתחות, למשל:
   ```
   GEMINI_API_KEY=...
   COHERE_API_KEY=...
   MISTRAL_API_KEY=...
   OPENROUTER_API_KEY=...
   ```
   שני הקבצים כבר ב-`.gitignore` ולא עולים לגיט. ב-`apps/web/.env.example` יש את כל האפשרויות, כולל Claude בתשלום.
   בגרסאות החינמיות, הספקים עשויים להשתמש בקלט לאימון. לכן עובדים רק עם נתוני הדוגמה, לא עם נתוני שכר אמיתיים.
4. מפעילים את האתר ופותחים בדפדפן את `http://localhost:3000`:
   ```
   npm run dev
   ```

תמונות הרכבים כבר בתיקייה `apps/web/public/cars`. כדי להוריד תמונות לרכבים חדשים בקטלוג:
```
npm run cars:images
```
בחיבור עם נטפרי, תמונה חדשה נשלחת קודם לבדיקה של נטפרי, והסקריפט מדלג עליה. מריצים אותו שוב אחרי שנטפרי מאשר.

בדיקות, בלי מפתח ובלי אינטרנט:
```
npm test
npm run typecheck
```

## הפעלה עם Docker

צריך Docker Desktop (או Docker Engine + Compose). לא צריך Node.js מותקן על המחשב.

1. יוצרים את `apps/web/.env` עם המפתחות, בדיוק כמו בהפעלה הרגילה (סעיף קודם).
2. מרימים:
   ```
   docker compose up --build
   ```
   ופותחים `http://localhost:3000`.

הנתונים (מאגר שווי השימוש וב-SQLite, ובעתיד גם היסטוריית השיחות) נשמרים ב-volume בשם `strauss_data`,
ושורדים `docker compose down` ו-`docker compose up` מחדש. למחיקה מלאה: `docker compose down -v`.

כדי לייבא את מאגר שווי השימוש (`data/source/value-of-use-2026.csv`) לתוך אותו volume, בלי Node מותקן מקומית:
```
docker compose run --rm data-import
```

## מסך הנציג

המסך נמצא ב-`http://localhost:3000/rep`. יש שתי דרכים להיכנס אליו:

- **סיסמה משותפת:** מגדירים `REP_PASSWORD` ב-`apps/web/.env`. מתאים לפיתוח ולדמו.
- **התחברות עם גוגל:** מגדירים `AUTH_SECRET`, `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET` ו-`REP_EMAILS`. רק המיילים שב-`REP_EMAILS` נכנסים, והסיסמה כבר לא בשימוש. ההסבר המלא, כולל איך מקבלים את המפתחות, נמצא ב-`apps/web/.env.example`.

## איך זה עובד

1. העובד כותב בצ'אט. השרת שולח את השיחה למודל השפה עם ההנחיות (`packages/agent/src/prompt.ts`) ועם רשימת הכלים.
2. המודל לא מחשב בעצמו. הוא מפעיל כלים: שמירת נתוני שכר, קטלוג רכבים, חיפוש במאגר, בדיקת זכאות, חישוב השוואה ושאלה לנציג.
3. הכלים קוראים למנוע החישוב. המנוע מחזיר מספרים מדויקים, והמסך מציג אותם בכרטיס השוואה.
4. כשחסר נתון שרק החברה יודעת, הבוט שולח שאלה לנציג ומציג בינתיים את מה שכבר חושב. כשהנציג עונה, הבוט ממשיך מאותה נקודה. עובד לא יכול להתחזות לנציג: הבוט קורא את התשובה מכלי, או מהודעת מערכת ב-Claude.
5. **מעבר אוטומטי בין ספקים:** הבוט מתחיל ב-Gemini. כשהמכסה של ספק נגמרת, או שהוא לא זמין, הבקשה עוברת מיד לספק הבא בתור (Cohere, Mistral, OpenRouter, Groq), אפילו באמצע חישוב. הספק שנכשל מקבל זמן המתנה, ואחריו חוזרים אליו. ההיסטוריה נשמרת בפורמט משותף (`packages/agent/src/free.ts`), ומתורגמת לפורמט של כל ספק. מתחת לכל תשובה במסך כתוב איזה ספק ענה.

## קבצי ההגדרות (`config`)

- `rules.json`: תקציבים, קבוצות, מסלול משפחתי, החזר חשמל, שיטת חישוב הנטו.
- `catalog.json`: 20 הרכבים בקטלוג (מגיליון "קטלוג רכבים").
- `occupations.json`: 14 העיסוקים, ומי מהם יכול לוותר על רכב.
- `sample-employees.json`: 6 העובדים לדוגמה.
- `reference-results.json`: נטו הייחוס של המארגנים. הבדיקות משוות אליו.

אם האקסל מתעדכן: `npm run config:build`. אחרי שינוי בקבצי ההגדרות מפעילים את השרת מחדש.

## מצב נוכחי

- **מנוע החישוב:** מוציא בדיוק את נטו הייחוס של המארגנים לכל 6 העובדים, כולל טקסט "למה". מקרי קצה בדוקים: ויתור בקבוצה ב', תפקיד שטח, בחירה מקבוצה גבוהה, מסלול משפחתי, פלאג-אין, השתתפות חסרה.
- **הבוט:** עובד בחינם עם שרשרת של Gemini 3.8 Flash, Cohere, Mistral, OpenRouter ו-Groq שמחליפים זה את זה, או עם Claude Opus 5.5 בתשלום. נבדק עם מפתחות אמיתיים של Gemini ו-OpenRouter: תור שלם עם שלושה כלים, נטו מדויק מהמנוע, וכ-9 שניות ב-Gemini. 9 כלים. ההיסטוריה נשמרת בשיטת "רק מוסיפים בסוף", ובדיקות אוטומטיות מוודאות את זה. ב-Claude מופעל מנגנון גיבוי: אם מסנן הבטיחות דוחה בטעות שאלה תמימה, השרת מנסה מודל חלופי.
- **האתר:** צ'אט מימין לשמאל, כרטיס השוואה עם כל הרכיבים, הודעת "ממתין לנציג" ובדיקה אוטומטית אם הנציג ענה. השיחה שורדת רענון של הדף.
- **עיצוב:** הדמות "נטבוט", מכונית מצוירת שמגיבה לשיחה: חושבת בזמן חישוב, שמחה כשהנטו עולה, מודאגת כשהוא יורד, ומחזיקה טלפון בהמתנה לנציג. מצוירת ב-SVG בקוד.
- **תמונות של הרכבים:** הבוט מציג תמונות כשהוא מציע רכבים, כשהעובד מספר איזה רכב יש לו, ובכרטיס ההשוואה. התמונות מוויקישיתוף, ברישיונות Creative Commons, עם קרדיט לצלם. כשאין תמונה מוצג ציור לפי סוג המרכב.
- **בלי לחכות לבוט:** בכרטיס ההשוואה יש פירוט "איך חושב?" עם כל שלבי החישוב, ואפשר לבחור רכב אחר ולחשב מחדש. בטופס "הנתונים שלי" אפשר לתקן שכר והפרשות. הפעולות האלה עוברות דרך אותם כלים ואותו מנוע, והבוט מקבל עליהן הודעה.
- **עדיין זמני:** השיחות נשמרות בזיכרון של השרת ונמחקות כשהוא עולה מחדש. החיפוש במאגר מכיר רק את רכבי הקטלוג. אין עדיין מסך נציג.

## החלטות שקיבלנו

- **מודל השפה:** בפיתוח, מפתחות חינמיים עם מעבר אוטומטי ביניהם, לפי ההמלצה של ארגז הכלים של ההאקתון. מפתח אחד לכל ספק: לא עוקפים מכסה של ספק בעזרת כמה מפתחות שלו. Claude Opus 5.5 נתמך באותו קוד.
- **Gemini 3.8 Flash עם חשיבה נמוכה:** gemini-2.5-flash כבר לא זמין למשתמשים חדשים. חשיבה נמוכה קיצרה תור מ-53 שניות ל-9, עם אותן תוצאות, כי החישוב נעשה בקוד.
- **פלאג-אין לא מקבל החזר חשמל.** הכלל מדבר על "רכב חשמלי". אפשר לשנות ב-`rules.json` בשדה `electric.eligibleDrives`.
- **רכב נוכחי שלא בקטלוג:** הבוט מחפש אותו במאגר רשות המסים. אם יש יותר מהתאמה אחת, הוא שואל את העובד או את הנציג.
- **ההפרש שמוצג לעובד** הוא נטו מעוגל בחלופה פחות נטו מעוגל היום, כמו אצל המארגנים.
- **תשובת נציג נכנסת רק כהודעת מערכת,** כך שעובד לא יכול להתחזות לנציג בצ'אט.

## נחמי: מאיפה להתחיל

1. **בדיקות אוטומטיות (N2):** GitHub Actions שמריץ `npm ci`, `npm run typecheck`, `npm test` ו-`npm run build`.
2. **מאגר רשות המסים (N3, N4):** לייבא את `data/source/value-of-use-2026.csv` ל-SQLite, ולממש את `DataSource` שב-`packages/agent/src/ports.ts`. הקובץ בקידוד cp1255, וצריך לנקות רווחים מכל השדות.
   - מפתח החיפוש חייב לכלול את קוד סוג הרכב. בלי זה, ATTO 3 ו-TANG מקבלים אותו מפתח.
   - הכותרת של עמודת ההנעה ב-CSV מטעה. הפירוש הנכון הוא זה שב-`rules.json`: 0 בנזין, 1 היברידי, 2 פלאג-אין, 3 חשמלי. זה נבדק מול כל 20 רכבי הקטלוג.
3. **מסד נתונים (N6):** להחליף את השמירה בזיכרון ב-`apps/web/lib/server.ts`. כל שיחה נשמרת כאובייקט `SessionState` אחד ועוד רשימת `transcript`. את `session.messages` שומרים בדיוק כמו שהם, בלי לערוך. כל פעולה על שיחה עוברת דרך `withLock`, כדי ששתי פעולות לא יכתבו להיסטוריה באותו זמן. עם מסד נתונים, הנעילה צריכה לעבוד גם בין כמה שרתים.
4. **מסך נציג (N7, N8):** ב-`apps/web/lib/server.ts` כבר יש `listOpenRepQuestions` ו-`answerRepQuestion`. צריך API ומסך `/rep` שקוראים להן. מסך העובד כבר בודק כל כמה שניות אם הנציג ענה.
5. החוזה המשותף נמצא ב-`packages/engine/src/types.ts` וב-`packages/agent/src/ports.ts`. שינוי שם דורש תיאום בינינו.

תוכנית העבודה המלאה: `תוכנית-עבודה-וחלוקה.md`.
